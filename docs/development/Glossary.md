# Glossary

| Term                    | Definition                                                                                                                                                                                                                                                                                                                      |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Direct Play             | Send the original media file exactly as stored. No changes to container, video, or audio.                                                                                                                                                                                                                                       |
| Direct Stream           | Keep the original video and audio codecs, but repackage them into a different container (for example, MKV → MP4)                                                                                                                                                                                                                |
| Transcode               | Re-encode the video and/or audio into formats, bitrates, or resolutions the client supports.                                                                                                                                                                                                                                    |
| Critical exception path | Scenario in use case that are worth testing                                                                                                                                                                                                                                                                                     |
| Standard User           | non-admin user                                                                                                                                                                                                                                                                                                                  |
| Admin                   | User with more privileges than a standard one                                                                                                                                                                                                                                                                                   |
| Root Admin              | First user with all the privileges                                                                                                                                                                                                                                                                                              |
| Domain Service          | A service in the domain is an object containing common buisness logic to multiple usecase. They shouldn't have dependencies and should be think as a last solution if multiple (more than 3) use case implement similar logic. Always prefer in the domain object representation first. They aren't declare as interface        |
| Log rotation            | Replace the active log file on a fixed period (`MINUTELY`, `HOURLY`, `DAILY`) or never; rotated files are pruned to `logging.max_files`.                                                                                                                                                                                        |
| Filter directives       | `tracing-subscriber` `EnvFilter` expression (for example `debug,sqlx=warn`) selecting which events reach the logs.                                                                                                                                                                                                              |
| Redaction               | Omitting or masking a secret or personal value before it can reach a log sink (`OBS-004`).                                                                                                                                                                                                                                      |
| Security event          | A catalogued event recording a security-relevant decision or outcome, such as an authentication or authorization result, emitted at its declared level (`OBS-006`).                                                                                                                                                             |
| Non-suppressible event  | A security event emitted on the reserved `security` target, which `logging.level` cannot suppress (`OBS-007`).                                                                                                                                                                                                                  |
| Log injection           | Forging or splitting a log record with control characters embedded in a client-supplied value; `OBS-003` prevents it by never logging a raw client value.                                                                                                                                                                       |
| Content Type            | The declared MIME type of a payload or file's content (for example `application/json` or `audio/mpeg`). It is metadata about the content and must not be trusted over content-based detection.                                                                                                                                  |
| Application use case    | A single operation of the application layer: the `port/<name>.rs` trait `<Name>UseCase` plus its `use_case/<name>.rs` implementation, exposing one `execute` method. The technical unit governed by [TechnicalDesign.md](TechnicalDesign.md) § 1 (Code Style Guidelines), § 9 (Use cases); not the same as a business use case. |
| Business use case       | A business capability catalogued in [UseCases.md](UseCases.md) as `UC-###` and initiated by an actor. Implemented by one or more application use cases and may span several requests.                                                                                                                                           |                                                                                                                                                                                                                                       |
