# Glossary

The canonical vocabulary for the project, covering both business and technical terms. Reuse a term from this table
before coining a new one; add a new term here before using it in a specification, design, task list, or other document.
Keep each definition to one concise sentence and state what the term is not when a nearby term could be confused. A
definition never cites a rule identifier or restates a rule's accepted values or configuration keys.

| Term                    | Definition                                                                                                                                                                                                                                                                                                                                                  |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Direct Play             | Send the original media file exactly as stored. No changes to container, video, or audio.                                                                                                                                                                                                                                                                   |
| Direct Stream           | Keep the original video and audio codecs, but repackage them into a different container (for example, MKV → MP4)                                                                                                                                                                                                                                            |
| Transcode               | Re-encode the video and/or audio into formats, bitrates, or resolutions the client supports.                                                                                                                                                                                                                                                                |
| Critical exception path | Scenario in use case that are worth testing                                                                                                                                                                                                                                                                                                                 |
| Standard User           | A non-admin user who owns and creates galleries, playlists and uploads and holds no account administration.                                                                                                                                                                                                                                                 |
| Admin                   | A user who curates the catalogue and creates and manages Standard accounts and their grants; a non-root caller cannot touch an Admin.                                                                                                                                                                                                                       |
| Root Admin              | The first user (identifier `0`), an implicit owner on every resource and never denied, except that an upload stays owner-only; only the root creates an Admin, changes a role or replaces a credential.                                                                                                                                                     |
| Domain Service          | A stateless object in the domain holding a business rule shared by two or more use cases. It depends only on domain models and values, holds no I/O, is declared as a concrete type rather than an interface, and is invoked by the application layer. Prefer a domain model's own invariant first; introduce a service when the same rule spans use cases. |
| Log rotation            | Replacing the active log file periodically and retaining only a bounded number of rotated files.                                                                                                                                                                                                                                                            |
| Filter directives       | A `tracing-subscriber` `EnvFilter` expression selecting which events reach the logs.                                                                                                                                                                                                                                                                        |
| Security event          | A catalogued event recording a security-relevant decision or outcome, such as an authentication or authorization result.                                                                                                                                                                                                                                    |
| Non-suppressible event  | A security event emitted on the reserved `security` target, which no log-level setting can suppress.                                                                                                                                                                                                                                                        |
| Log injection           | Forging or splitting a log record with control characters embedded in a client-supplied value.                                                                                                                                                                                                                                                              |
| Security-event catalog  | The closed set of `security`-target events, each with its severity, fields and recorded-when trigger.                                                                                                                                                                                                                                                       |
| Content Type            | The declared MIME type of a payload or file's content (for example `application/json` or `audio/mpeg`). It is metadata about the content and must not be trusted over content-based detection.                                                                                                                                                              |
| Upload session          | A resumable, chunked intake of one declared file, owned by the caller and fixed at creation to a chunk size and an expiry instant.                                                                                                                                                                                                                          |
| Chunk                   | One byte range of an upload session's content, stored at its declared offset and recorded in the session's received-chunk bitmap.                                                                                                                                                                                                                           |
| Staged content          | The server-owned file an upload session writes before completion promotes it under the library root; it is not a stored file and is never addressed as one.                                                                                                                                                                                                 |
| Library root            | The operator-supplied directory, relative to the working directory, that holds every stored file at a root-relative path; the server never creates it.                                                                                                                                                                                                      |
| Integrity hash          | The 64-character hexadecimal SHA-256 digest of a complete file's content, declared when a session begins and recomputed before completion registers the bytes.                                                                                                                                                                                              |
| Application use case    | A single operation of the application layer: the `port/<name>.rs` trait `<Name>UseCase` plus its `use_case/<name>.rs` implementation, exposing one `execute` method. The technical unit governed by [TechnicalDesign.md](TechnicalDesign.md) § 1 (Code Style Guidelines), § 1.9 (Use cases); not the same as a business use case.                           |
| Business use case       | A business capability catalogued in [UseCases.md](UseCases.md) as `UC-###` and initiated by an actor. Implemented by one or more application use cases and may span several requests.                                                                                                                                                                       |
| Triggering event        | The single external, state-changing event that starts a use case: it originates with an actor, an external system or a timer, is a discrete event rather than an ongoing state, is not a precondition, and says nothing about the flow it starts. It names the event, never the entry point that carries it: no field of an entry names a route.            |
| Parameters              | The data the triggering event carries into a use case: one bullet per input, named in business vocabulary with its optionality, never a request field, a type or a schema fragment.                                                                                                                                                                         |
| Caller                  | The authenticated actor on whose behalf the system runs a use case. An entry writes “the caller” when its rule holds for every role, and names the actor when the role decides the outcome.                                                                                                                                                                 |
| Resource                | An authorizable entity stored as one row with a kind, an optional owner, one authorization parent and a visibility; not every database entity is a resource.                                                                                                                                                                                                |
| Resource kind           | The category of a resource (`GALLERY`, `MOVIE`, `MUSIC_RECORDING`, `USER`), used to address it and to constrain a `CreateChild` action.                                                                                                                                                                                                                     |
| Catalogue               | The unowned resource container under the library that holds films, shows, albums, music groups and their children; distinct from user content, which is a gallery or a playlist under the library.                                                                                                                                                          |
| Authorization parent    | The single canonical edge through which a resource inherits permissions from its parent; it is not the containment or display parent.                                                                                                                                                                                                                       |
| Resource relation       | A containment or reference edge (`AlbumMember`, `PlaylistEntry`, `GroupMember`) that lends `Discover`, `ViewMetadata`, `View` and `Stream` to its target and the target's authorization-parent descendants, but never download, write, share or admin authority; distinct from an authorization parent.                                                     |
| Principal               | The subject a grant applies to: a user, a role or the root.                                                                                                                                                                                                                                                                                                 |
| Grant                   | A stored permission record naming a principal, a resource, a resource role, a child kind and an `Allow` or `Deny` effect; the unit of sharing, not a per-action scope.                                                                                                                                                                                      |
| Resource role           | A named bundle of actions (`Viewer`, `Downloader`, `Contributor`, `Editor`, `Manager`, `Owner`) granted on a resource; `Owner` is implicit for a user and is never stored as a user grant, while a seeded role grant may carry it.                                                                                                                          |
| Child kind              | The `ChildKind` a `CreateChild` action names, such as a gallery, a playlist, a film or a user; `ChildKind::Admin` is root-only and not grantable.                                                                                                                                                                                                           |
| Creation surface        | A resource that exists only as the anchor of a `CreateChild` grant (`GALLERY_COLLECTION`, `PLAYLIST_COLLECTION`, `UPLOAD_COLLECTION`, `USER_COLLECTION`); it holds no content child, and a created child's authorization parent is the surface's parent, never the surface.                                                                                 |
| Owner                   | The user a resource belongs to, resolved as the nearest non-null owner up the authorization-parent chain; the owner holds the implicit `Owner` resource role, and a catalogue resource has no owner.                                                                                                                                                        |
| Visibility              | The coarse resource-level grant: `Private` adds none, `Restricted` adds discovery and metadata to authenticated callers, and `Public` adds the viewer actions; none implies download, edit, share or delete, and visibility is not inherited.                                                                                                               |
| Position                | The place of an entry in an ordered collection, such as a track in a playlist or an item in a gallery, used to address and order it; a new entry is appended after the last one.                                                                                                                                                                            |
| Last-modified time      | The moment a collection last changed, such as a playlist or a gallery. Every successful change advances it, including a change that stores no new value.                                                                                                                                                                                                    |
| System                  | The service under design, named as the executor of a use case's happy path and alternative flows. It is never an actor: a trigger only the system can produce breaks the external-origin rule of a `Triggering event`.                                                                                                                                      |
| Action                  | One authorizable operation from the fixed catalog (`Discover`, `ViewMetadata`, `View`, `Stream`, `Download`, `CreateChild`, `EditMetadata`, `ReplaceMedia`, `Share`, `ManagePermissions`, `Delete`, `ChangeRole`, `ReplaceCredential`), decided against one resource.                                                                                       |
| Who-may rule            | The statement of which caller may perform an action and under which grant; a feature specification names the action but never restates the rule, which only its owning capability states.                                                                                                                                                                   |
| API index               | The public HAL document at `/api/v1` that links the authentication operations, each context's entry point and the liveness probe; it is caller-independent and lists no item routes.                                                                                                                                                                        |
| Partial representation  | A browse-only representation of an item in a catalog collection, carrying its identifier, name, cover and links; distinct from the full detail representation.                                                                                                                                                                                              |
| Metadata enrichment     | The pipeline that turns a media name or a query into provider-independent candidates, resolves one into provider-independent metadata through the provider that issued its reference, and applies that metadata to the catalogue; identification and application are its two stages, and neither is a synonym for it.                                       |
| Provider reference      | An opaque identifier a metadata provider issues for one work, tagged with the provider that issued it, which a resolution or an apply addresses; it carries no metadata and names no route.                                                                                                                                                                 |
| Instance state          | The non-derivable part of an instance — the site pepper, the token signing secret and the instant it was established — persisted in `state.yaml` and never silently replaced.                                                                                                                                                                               |
| Site pepper             | The secret mixed into every password hash; part of the instance state and never configuration.                                                                                                                                                                                                                                                              |
| Token signing secret    | The secret that signs and verifies access tokens; part of the instance state and never configuration.                                                                                                                                                                                                                                                       |
| Instance root           | The working directory the server runs against (`/app` in the image), holding `state.yaml`, `config.yaml`, `mnemorium.db` and the library mount; its owner is the account the state file must belong to, not the Root Admin.                                                                                                                                 |
| Typed asset             | A stored file's media row, an `image`, an `audio` or a `video`, read through its own resource — identifier, characteristics, representation and `file` alias — which holds no bytes itself and is not the stored file that backs it.                                                                                                                        |
| Image                   | The typed asset an image file backs: the name the intake assigned, positive dimensions, the orientation derived from those dimensions and the creation date.                                                                                                                                                                                                |
| Audio                   | The typed asset an audio file backs: the name the intake assigned and the codec, plus the duration, sample rate, bit depth and block size the content reports, each absent when it reports none.                                                                                                                                                            |
| Video                   | The typed asset a video file backs: the codec, colour identifier, duration, frame count, dimensions and scan type, and no name; a film or an episode embeds a summary of it rather than the whole representation.                                                                                                                                           |
| Movie                   | The catalogue resource a film names: a name, plot, country of origin, release date, genres ordered by identifier, artwork and the one video that backs it; film is a synonym, and a movie is never an episode.                                                                                                                                              |
| Series                  | The catalogue resource a show names: a name, plot, country of origin, first air date, genres ordered by identifier, artwork and the seasons ordered by index; show is a synonym, and a series is never an episode.                                                                                                                                          |
| Season                  | One indexed part of a show, carrying a name, artwork and the episodes ordered by index; its identity is its index within the show, not a surrogate identifier.                                                                                                                                                                                              |
| Episode                 | One indexed part of a season, carrying a name, plot, air date and the one video that backs it; its identity is its index within the season, not a surrogate identifier.                                                                                                                                                                                     |
| Asset scope             | The class that fixes which first attachment uses a stored image or video — `Library` for catalogue artwork, `User` for gallery media or a playlist cover; absent until that attachment and never changed afterwards, and not part of any typed asset representation.                                                                                        |
| Gallery                 | An owned, ordered collection of image and video items, created and browsed under the Library context; it carries a name, visibility, item count and last-modified time and no artwork.                                                                                                                                                                      |
| Gallery item            | One membership of exactly one image or one video in a gallery, carrying its position and the instant it was added.                                                                                                                                                                                                                                          |
| Default gallery         | The seeded gallery with identifier `0`, ownerless and public, that every caller may read and that is never deletable.                                                                                                                                                                                                                                       |
| Orientation             | The classification of an image by its dimensions: `LANDSCAPE` when the width exceeds the height, `PORTRAIT` when the height exceeds the width and `SQUARE` when they are equal.                                                                                                                                                                             |
| Scan type               | The classification of a video's scan from the closed set `PROGRESSIVE`, `INTERLACED`, `MBAFF` and `PAFF`.                                                                                                                                                                                                                                                   |
| Cover art               | The optional artwork a resource stores as a reference to one image row whose scope the first attachment fixes — library scope for a catalogue resource, user scope for a playlist — with at most one referrer.                                                                                                                                              |
